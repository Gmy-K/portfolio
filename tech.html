開発物の仕組み

Claude Code のスキル、VOICEVOX 調声、留学の家計簿。自分用に作った3つを、図つきで説明します。

  • ① Claude Code スキル集
  • ② VOICEVOX 調声スキル
  • ③ 留学の家計簿

WORK 1

① Claude Code スキル集（学習・発信の自動化）

ひとことで：AI（Claude Code）に「この作業は、この手順でやる」と教えておく手順書（スキル）を、用途ごとに作りためています。頼むと、毎回同じ手順で動いてくれます。

作った理由

  • 毎回、同じ説明を AI にするのが面倒。
  • 頼み方によって、結果がぶれる。
  • 守ってほしいルール（書き換えない、先に答えを見ないなど）を、毎回伝え忘れる。

仕組み

1. 頼む

例：「リアクションペーパーを書いて」

2. スキルを選ぶ

AI が、頼み方に合うスキルを選んで読む。

3. 実行する

「守ること」と「手順」のとおりに動く。

4. 結果

ノート、文章、提案など。

スキルの中身

1つのスキルは、1つのフォルダです。中に、手順書（Markdown の SKILL.md）が1枚あります。先頭に「どんな頼まれ方のときに使うか」、本文に「守ること」と「手順」を書きます。

できること

スキルでできることの一覧
分野できること
講義・試験講義スライド（PDF）をノートに転記する／講義ノートからリアクションペーパーを書く／講義ノートを根拠にして試験問題の解答を作る
英単語手書きの英単語カードをデジタル化し、検索できるノートにする
タスク・復習タスクの登録・細分化・完了／毎週の決まり事のタスク化／復習問題づくりと、毎日の復習
毎日の確認今日のブリーフィング／Web ダッシュボードの更新
発信・動画留学Noteの記事づくり／VOICEVOX の調声の提案

大学の学習支援として作ったスキルは14個です。ほかに、サークル活動のイベント計画用のスキルが1つあります。

工夫した点

  • 「守ること」を先に書く。例：復習では、正解を先に見せない。ユーザーの理由を書き換えない。タスクの完了は、名前を挙げたものだけにチェックを付ける。
  • 範囲を絞る。例：単語カードは、「文字にする」と「ノートにする」を別のスキルに分けました。
  • 理由を残す。作るたびに、なぜそうしたかを、設計の記録（ADR）に残します。
  • 直しやすい。手順を変えたくなったら、手順書を直すだけで、次から全部に反映されます。

作り方

  1. 設計
  2. 手順書を書く
  3. 実際に頼んで試す
  4. 失敗した例を手順書に足す

設定ファイルをまとめたリポジトリで、バージョン管理しています。スキルまわりの設計の記録は5本です。

技術メモ

  • Claude Code スキル
  • Markdown
  • Git
  • 設計の記録（ADR）

WORK 2

② VOICEVOX 調声スキル（セリフから調声パラメータを提案）

ひとことで：セリフ・キャラクター名・トーン（例：淡々とシュール）を伝えると、VOICEVOX の調声パラメータ（話速・音高・抑揚・音量・間・無音）の推奨値を提案するスキルです。留学 Vlog のナレーションを作るときに使っています。

解決したかった悩み

  • Reel のナレーションは、何本ものセリフを、少しずつ違うトーンで調声する。
  • 毎回、手探りで数値を決めるのが大変だった。

仕組み

入力

  • セリフ本文
  • キャラ名
  • トーンの説明（自由な文で）

プリセットを選ぶ

5つの中から、トーンに最も近いものを選ぶ。

  • 淡々・シュール系
  • ハイテンション・早口系
  • 感情豊か・親近感系
  • 落ち着いたナレーション系
  • その他

微調整する

セリフ本文を走査して、数値を直す。

  • 40字以上は、話速を少し上げる
  • 「！」があれば、抑揚を上げる
  • 読点が多ければ、間を長くする
  • 10字未満の決め台詞は、前後の無音を足す

出力

表で返す。VOICEVOX の画面のパラメータの並びと同じなので、見ながらそのままスライダーに転記できる。

工夫した点

  • 数値は「出発点」。実測ではないと、毎回、注記します。
  • 数値にしないものがある。疑問形のイントネーションや、固有名詞のアクセントは、「手動で確認」と注記します。
  • 数値を創作しない。言葉だけで書かれたもの（例：「普通〜やや長め」）には、数値を付けません。
  • 音声は作らない。音声そのものは生成しません。VOICEVOX の画面で、手動で反映します。

設計の選択

3つの方法を比べました。

  • （A）固定の表だけ
  • （B）セリフごとにルールで組み立てる
  • （C）表を土台にして、ルールで微調整する

安定感と、その回だけの個性を両立できる（C）を選びました（設計の記録 ADR 008）。

作り方

設計をしてから、手順書を書きました。プリセットと微調整のルールは、手順書に静的に書いています。

技術メモ

  • Claude Code スキル
  • VOICEVOX
  • Markdown
  • 設計の記録（ADR）

WORK 3

③ 留学の家計簿（支出の記録と予算のペース表示）

ひとことで：留学中の支出を、スマホから数秒で記録して、今月の予算に対するペースを見られる、自分用の Web アプリです。

解決したかった悩み

  • キャッシュレス（カードのタップ）が主流で、少額の支払いが1日に何度もある。
  • 入力が面倒だと、続かない。

仕組み（3つの部品）

画面

HTML と JavaScript で作る。グラフは Chart.js。

計算

純粋な関数だけを集めたファイル。画面とデータから切り離してあり、Node.js でテストできる。

データ

クラウド上の小さなデータベース。スマホでもパソコンでも、同じデータを使える。個人用なので、ログインはない。

Claude の Artifact（小さな Web アプリの置き場）として作りました。1つの URL をブックマークすれば使えます。

画面でできること

  • 支出を、すばやく記録する。
  • 今月の使った額を、予算と比べて見る（日割りのペースの目印つき）。
  • 日ごとの支出のグラフ。
  • 残高の見通し。
  • 固定費と変動費に分けた、お金の流れ。
  • 食事つきの住居の、食事の回数に応じた食費の予算の自動調整。
  • 送金プランの管理。

工夫した点

  • 入力の手間を、できるだけ小さくする。設計上、最も重要な制約です。
  • 計算を画面から切り離して、テストを書いた。
  • 先に設計。機能ごとに、設計書と実装計画を書いてから作りました。
  • 決めたことを、設計の記録（ADR）に残した。4本あります。
    • 休暇・食事回数のデータは、計算ファイルの定数にする。
    • 休暇月の食費予算は、食事の回数の比で自動で増やし、表示にだけ反映する。
    • 送金の設定は、別のデータ文書に持つ。
    • 月の資産の増減は、記録から計算する。

作り方

機能ごとに「設計書 → 実装計画 → テスト先行で実装」を繰り返しました。

技術メモ

  • HTML
  • JavaScript
  • Chart.js
  • Claude Artifact（データベース機能）
  • Node.js（テスト）
  • 設計の記録（ADR 4本）
