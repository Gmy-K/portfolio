PKM(개인 지식 관리)의 구조

PKM(Personal Knowledge Management, 개인 지식 관리)으로서 저를 위해 만든 두 가지 시스템을 그림과 함께 설명할게요.

  • PKM① 학습 할 일 비서
  • PKM② Vault 전체 설계

SYSTEM 1

PKM① 학습 할 일 자동 비서 시스템 (아침 알림·역산 플래너)

한마디로: 노트(Obsidian)에 쌓인 과제와 일정을 매일 아침 자동으로 정리해서 스마트폰으로 보내 주는 시스템이에요. 마감일부터 거꾸로 계산해서 ‘오늘은 이걸 하면 좋아요’를 이유와 함께 알려 줘요.

해결하고 싶었던 고민

  • 한 주를 보내고 나면 다음 주 수업 일정이 흐릿해져서, 예습이 늘 아슬아슬해진다.
  • 할 일이 넘쳐서 무엇부터 손대야 할지 모르겠다.
  • 아침에 노트 여는 걸 깜빡한다.
  • 노트에 정보가 쌓이기만 할 뿐, 내 것이 됐다는 느낌이 들지 않는다.

구조

입력

  • 주간 반복 일정 (예습·쪽지 시험 등을 요일과 소요 시간과 함께 적어 둔 파일)
  • 수업·일정 (Google 캘린더)
  • 등록한 할 일 (노트)

역산 계산

  • 마감이 가까운 순서대로 빈 시간(일정·식사·장보기 제외)에 배분한다.
  • 다 들어가지 않는 것은 ‘들어갈 자리가 없음’이라고 표시한다.
  • AI는 쓰지 않고, 정해진 규칙으로 계산한다 (매번 같은 결과가 나오고, 테스트할 수 있다).

출력

  • 아침 알림 (클라우드가 매일 아침 자동으로 보냄)
  • 웹 대시보드 (스마트폰용, 매일 아침 자동 업데이트)

끝나면: 노트에서 체크 표시를 하거나, AI에게 ‘○○ 끝났어’라고 말해요.

다섯 가지 구성 요소

  1. 노트 (Obsidian, Git으로 관리) 할 일은 마감일·받은 날·소요 시간 같은 항목이 붙은 한 줄이에요. 부모·자식 할 일로 잘게 나눌 수도 있어요.
  2. 반복 일정 파일 매주 하는 예습이나 쪽지 시험 등을 적어 두면, 앞으로 2주 치 할 일을 자동으로 만들어요.
  3. 역산 계산 위의 그림과 같아요.
  4. 아침 알림 클라우드의 정기 실행이 매일 아침 한 통으로 묶어서 보내요. 컴퓨터를 덮어 둬도 작동해요.
  5. 웹 대시보드 오늘 일정, 다음에 할 일(긴급×중요의 네 칸), 12주 캘린더, 주별 작업량을 한 화면에서 볼 수 있어요. 비공개예요.

신경 쓴 점

  • 완료 추적을 기존 조작에 얹었다. 반복 일정도 실제 할 일로 만들어지기 때문에, 체크만 하면 끝이에요. 전용 화면이나 기록은 필요 없어요.
  • 쉽게 망가지지 않게. 계획 부분이 실패해도 아침 알림은 멈추지 않아요. 불러오지 못한 일정은 ‘일정 없음’으로 덮어쓰지 않아요. 같은 할 일은 두 번 만들지 않아요.
  • 계속 쓰기 위한 작은 기능. 만드는 걸 깜빡하면 아침 알림이 알려 줘요. 중요 표시는 버튼 하나로 붙였다 뗄 수 있어요.
  • 시간 어긋남에 대한 대비. 클라우드의 정시 실행은 붐비는 시간대에는 늦어지거나 빠지기도 한다는 걸 알게 됐어요. 그래서 시간을 옮기고, 보험용 두 번째 실행과 중복 발송을 막는 판정을 더했어요.

만든 방법 (개발 진행 방식)

AI(Claude Code)와 함께 설계서·결정 기록(ADR)·구현 계획을 먼저 쓰고, 테스트를 먼저 작성하는 방식으로 구현했어요. 작업마다 구현 담당과 리뷰 담당을 나누고, 마지막에 전체 리뷰를 거쳐요. 의존 라이브러리 없는 Node.js로 만들었고, 테스트 파일은 24개예요.

기술 메모

  • Node.js (의존성 없음)
  • Obsidian + Dataview
  • Git
  • GitHub Actions (정시 실행)
  • Discord 알림
  • Google 캘린더
  • AI 클라우드 정기 실행
  • HTML + 순수 JavaScript
  • 테스트 주도 개발
  • 설계 기록 (ADR 7개)

SYSTEM 2

PKM② Obsidian Vault 전체 설계

Vault(노트 보관소)는 번호가 붙은 폴더로 ‘정보의 흐름’을 나타내요.

폴더 지도

폴더 이름과 역할 대응표
폴더역할
00_Inbox정리 전의 임시 보관함
10_Fleeting일시적인 것 (일간·주간 노트, 새 할 일을 적는 곳)
20_Literature강의 노트·독서 메모·영어 단어
30_Zettel개념 카드 (내 말로 쓰는 지식)
40_MOC목차·대시보드
50_Projects실행하는 프로젝트
60_Review복습 문제 (선택 + 이유). 답이 개념 카드의 씨앗이 된다
80_System시스템 그 자체 (템플릿·스크립트·반복 일정)
90_Archive완료·보관

다섯 개의 층

  1. ①수집 층

    강의·독서. 강의 노트는 템플릿에 따라 써요(요약, 강의 메모, 모르는 어휘, 다음 행동, 중요한 개념). 과목마다 ‘평가·일정 요약’과 ‘현재 진행 중인 과제’ 노트를 둬요.

  2. ②할 일의 층

    한 줄로 통일된 서식(마감일·받은 날·소요 시간·상태). 새 할 일은 하나의 보관함에 들어가요. 주간 반복 일정은 자동으로 할 일이 돼요. 중요 표시는 버튼 하나예요.

  3. ③시간축의 층 (보기)

    캘린더 계열 플러그인, Dataview 목록, 간트 차트, 스마트폰용 웹 대시보드.

  4. ④자동화의 층

    Node.js 스크립트(의존성 없음, 테스트 24개), GitHub Actions의 매일 아침 알림, AI 클라우드 정기 실행(대시보드 업데이트), QuickAdd 매크로.

  5. ⑤지식으로 남기는 층

    복습 문제에 ‘제 말로 쓴 이유’와 함께 답하면 개념 카드의 씨앗이 돼요. 노트끼리의 연관은 AI에게 찾아 달라고 해요.

정보의 흐름

  1. 강의·독서
  2. 강의 노트
  3. 다음 행동
  4. 할 일
  1. 반복 일정
  2. 할 일
  1. 캘린더
  2. 역산 계산
  3. 아침 알림·웹 대시보드·Obsidian 목록

끝나면 노트에서 체크 표시를 해요.

AI와의 역할 분담

규칙은 노트 안의 지시서에 적어 두고, AI는 그걸 매번 읽어요. AI의 ‘스킬’이 강의 내용 옮겨 적기, 리액션 페이퍼(수업 소감문), 시험 대비, 할 일 등록, 복습, 대시보드 업데이트 등을 도와줘요. 계산은 AI에게 맡기지 않고, 정해진 규칙의 스크립트로 해요. AI는 쓰고, 정리하고, 절차를 실행하는 역할이에요.

데이터 저장 위치와 동기화

Vault 전체가 Git 비공개 저장소예요. 자동으로 커밋·push돼요. 아침 알림과 대시보드는 GitHub에 있는 그 사본을 읽어요. 비밀 정보(알림을 보낼 곳, 캘린더 URL)는 저장소에 넣지 않고, 클라우드의 비밀 보관소에 둬요.

지금 상태 (솔직하게 말하면)

  • 잘 쓰고 있는 것: 강의 노트·할 일·아침 알림·대시보드·캘린더.
  • 아직 덜 자란 것: 개념 카드와 복습 문제 (앞으로 늘려 갈 거예요).
  • 예전 그대로 남아 있는 것: 이전 학기의 루틴 (새로운 반복 일정 파일로 이미 옮겼어요).
