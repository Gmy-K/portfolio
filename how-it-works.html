PKM（個人の知識管理）の仕組み

PKM（パーソナル・ナレッジ・マネジメント＝個人の知識管理）として、自分用に作った2つの仕組みを、図つきで説明します。

  • PKM① 学習タスクの秘書
  • PKM② Vault の全体設計

SYSTEM 1

PKM① 学習タスクの自動秘書システム（朝の通知・逆算プランナー）

ひとことで：ノート（Obsidian）に溜まった課題と予定を、毎朝、自動で整理してスマホに届ける仕組みです。期限から逆算して、「今日はこれをやるとよい」を、理由つきで教えてくれます。

解決したかった悩み

  • 一週間を過ごすと、次の週の授業の予定がぼんやりして、予習がギリギリになる。
  • タスクが溢れて、何から手をつけるか分からない。
  • 朝にノートを開き忘れる。
  • ノートに情報が溜まるだけで、自分のものになっている感じがしない。

仕組み

入力

  • 毎週の決まり事（予習・小テストなどを、曜日と所要時間つきで書いたファイル）
  • 授業・予定（Google カレンダー）
  • 登録したタスク（ノート）

逆算の計算

  • 期限が近い順に、空き時間（予定・食事・買い出しを除く）へ割り振る。
  • 収まらないものは「収まらない」と出す。
  • AI は使わず、決まったルールで計算する（毎回同じ結果になり、テストできる）。

出力

  • 朝の通知（クラウドが毎朝、自動で送る）
  • Web ダッシュボード（スマホ用、毎朝自動で更新）

終わったら：ノートでチェックを付ける、または「〇〇終わった」と AI に言います。

5つの部品

  1. ノート（Obsidian、Git で管理）タスクは、期限・もらった日・所要時間などの項目つきの1行です。親子のタスクで細分化もできます。
  2. 決まり事のファイル毎週の予習や小テストなどを書いておくと、今後2週間ぶんのタスクを自動で作ります。
  3. 逆算の計算上の図のとおりです。
  4. 朝の通知クラウドの定期実行が、毎朝、1通にまとめて送ります。パソコンを閉じていても動きます。
  5. Web ダッシュボード今日の予定、次にやること（緊急×重要の4つの箱）、12週のカレンダー、週ごとの負荷を、1枚で見られます。非公開です。

工夫した点

  • 完了の追跡を、既存の操作に乗せた。決まり事は実タスクとして作るので、チェックを付ければ終わりです。専用の画面や記録は要りません。
  • 壊れにくさ。計画の部分が失敗しても、朝の通知は止まりません。取れなかった予定は、予定なしで上書きしません。同じタスクは2回作りません。
  • 使い続けるための小さな機能。作り忘れたら、朝の通知が教えてくれます。重要度は、ボタン1つで付け外しできます。
  • 時刻のずれへの備え。クラウドの定時実行は、混む時刻だと遅れたり抜けたりすることが分かりました。そこで時刻をずらし、保険の2本目と、二重送信を防ぐ判定を足しました。

作り方（開発の進め方）

AI（Claude Code）と一緒に、設計書・決定の記録（ADR）・実装計画を書いてから、テスト先行で実装しました。作業ごとに、実装役とレビュー役を分け、最後に全体のレビューを通します。依存ライブラリなしの Node.js で、24本のテストファイルがあります。

技術メモ

  • Node.js（依存なし）
  • Obsidian＋Dataview
  • Git
  • GitHub Actions（定時実行）
  • Discord への通知
  • Google カレンダー
  • AI のクラウド定期実行
  • HTML＋素の JavaScript
  • テスト先行開発
  • 設計の記録（ADR 7本）

SYSTEM 2

PKM② Obsidian Vault の全体設計

Vault（ノートの保管庫）は、番号つきのフォルダで、「情報の流れ」を表しています。

フォルダの地図

フォルダ名と役割の対応表
フォルダ役割
00_Inbox未整理の受け皿
10_Fleeting一時的なもの（日・週のノート、新しいタスクの書き込み先）
20_Literature講義ノート・読書メモ・英単語
30_Zettel概念カード（自分の言葉で書く知識）
40_MOC目次・ダッシュボード
50_Projects実行するプロジェクト
60_Review復習問題（選択＋理由）。解答は概念カードの種になる
80_System仕組みそのもの（テンプレート・スクリプト・決まり事）
90_Archive完了・保管

5つの層

  1. ①取り込む層

    講義・読書。講義ノートはテンプレートに沿って書きます（要約、講義メモ、分からない語彙、次のアクション、重要な概念）。科目ごとに「評価・日程の要約」と「今の課題」のノートを置きます。

  2. ②タスクの層

    1行の統一書式（期限・もらった日・所要時間・状態）。新しいタスクは1つの受け皿に入ります。毎週の決まり事は自動でタスク化します。重要度はボタン1つです。

  3. ③時間軸の層（見る）

    カレンダー系のプラグイン、Dataview の一覧、ガント、スマホ用の Web ダッシュボード。

  4. ④自動化の層

    Node.js のスクリプト（依存なし、24本のテスト）、GitHub Actions の毎朝の通知、AI のクラウド定期実行（ダッシュボード更新）、QuickAdd のマクロ。

  5. ⑤知識として残す層

    復習問題に「自分の言葉の理由」つきで答えると、概念カードの種になります。AI にノート同士の関連を探してもらいます。

情報の流れ

  1. 講義・読書
  2. 講義ノート
  3. 次のアクション
  4. タスク
  1. 決まり事
  2. タスク
  1. カレンダー
  2. 逆算の計算
  3. 朝の通知・Web ダッシュボード・Obsidian の一覧

終わったら、ノートでチェックを付けます。

AI との分担

ルールはノートの中の指示書に書き、AI はそれを毎回読みます。AI の「スキル」が、講義の転記、リアクションペーパー、試験対策、タスク登録、復習、ダッシュボード更新などを手伝います。計算は AI に任せず、決まったルールのスクリプトで行います。AI は、書く・まとめる・手順を実行する役です。

データの置き場所と同期

Vault 全体が Git の非公開リポジトリです。自動でコミット・push されます。朝の通知とダッシュボードは、その GitHub 上のコピーを読みます。秘密（通知の宛先、カレンダーの URL）は、リポジトリに入れず、クラウドの秘密の保管庫に置きます。

いまの状態（正直なところ）

  • よく使われている：講義ノート・タスク・朝の通知・ダッシュボード・カレンダー。
  • まだ育っていない：概念カードと復習問題（これから増やします）。
  • 古いまま残っている：以前の学期のルーチン（新しい決まり事のファイルに移行済み）。
