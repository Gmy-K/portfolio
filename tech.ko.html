직접 만든 것들의 구조

Claude Code 스킬, VOICEVOX 음성 조율, 유학 가계부. 저를 위해 만든 세 가지를 그림과 함께 설명할게요.

  • ① Claude Code 스킬 모음
  • ② VOICEVOX 음성 조율 스킬
  • ③ 유학 가계부

WORK 1

① Claude Code 스킬 모음 (학습·콘텐츠 제작 자동화)

한마디로: AI(Claude Code)에게 ‘이 작업은 이 순서로 한다’고 가르쳐 두는 설명서(스킬)를 용도별로 하나씩 만들어 모으고 있어요. 부탁하면 매번 같은 순서로 움직여 줘요.

만든 이유

  • 매번 AI에게 같은 설명을 하는 게 번거롭다.
  • 부탁하는 방식에 따라 결과가 들쭉날쭉하다.
  • 지켜 줬으면 하는 규칙(고쳐 쓰지 않기, 답을 먼저 보지 않기 등)을 매번 전하는 걸 깜빡한다.

구조

1. 부탁한다

예: ‘리액션 페이퍼 써 줘’

2. 스킬을 고른다

AI가 부탁 내용에 맞는 스킬을 골라 읽는다.

3. 실행한다

‘지킬 것’과 ‘순서’대로 움직인다.

4. 결과

노트, 글, 제안 등.

스킬의 내용물

스킬 하나는 폴더 하나예요. 그 안에 설명서(Markdown으로 쓴 SKILL.md)가 한 장 들어 있어요. 맨 앞에는 ‘어떤 부탁을 받았을 때 쓰는지’를, 본문에는 ‘지킬 것’과 ‘순서’를 적어요.

할 수 있는 일

스킬로 할 수 있는 일 목록
분야할 수 있는 일
강의·시험강의 슬라이드(PDF)를 노트에 옮겨 적기 / 강의 노트로 리액션 페이퍼(수업 소감문) 쓰기 / 강의 노트를 근거로 시험 문제의 답안 만들기
영어 단어손으로 쓴 영어 단어 카드를 디지털화해서 검색할 수 있는 노트로 만들기
할 일·복습할 일 등록·세분화·완료 / 매주 정해진 일을 할 일로 만들기 / 복습 문제 만들기와 매일 복습
매일 확인오늘의 브리핑 / 웹 대시보드 업데이트
콘텐츠·영상유학 Note 글쓰기 / VOICEVOX 음성 조율 제안

대학 공부를 돕기 위해 만든 스킬은 14개예요. 그 밖에 동아리 활동의 행사 계획용 스킬이 하나 있어요.

신경 쓴 점

  • ‘지킬 것’을 먼저 쓴다. 예: 복습에서는 정답을 먼저 보여 주지 않아요. 사용자가 쓴 이유를 고쳐 쓰지 않아요. 할 일 완료는 이름을 말한 것에만 체크해요.
  • 범위를 좁힌다. 예: 단어 카드는 ‘글자로 옮기기’와 ‘노트로 만들기’를 서로 다른 스킬로 나눴어요.
  • 이유를 남긴다. 만들 때마다 왜 그렇게 했는지를 설계 기록(ADR)에 남겨요.
  • 고치기 쉽다. 순서를 바꾸고 싶으면 설명서만 고치면 다음부터 전부에 반영돼요.

만든 방법

  1. 설계
  2. 설명서 쓰기
  3. 실제로 부탁해서 시험해 보기
  4. 실패한 사례를 설명서에 추가하기

설정 파일을 모아 둔 저장소에서 버전 관리하고 있어요. 스킬 관련 설계 기록은 5개예요.

기술 메모

  • Claude Code 스킬
  • Markdown
  • Git
  • 설계 기록 (ADR)

WORK 2

② VOICEVOX 음성 조율 스킬 (대사로부터 조율 파라미터를 제안)

한마디로: 대사·캐릭터 이름·톤(예: 담담하고 엉뚱하게)을 알려 주면, VOICEVOX의 음성 조율 파라미터(말하기 속도·음높이·억양·음량·쉼·무음)의 추천값을 제안하는 스킬이에요. 유학 Vlog의 내레이션을 만들 때 쓰고 있어요.

해결하고 싶었던 고민

  • Reel 내레이션은 여러 개의 대사를 조금씩 다른 톤으로 조율해야 한다.
  • 매번 더듬더듬 수치를 정하는 게 힘들었다.

구조

입력

  • 대사 본문
  • 캐릭터 이름
  • 톤 설명 (자유롭게)

프리셋 고르기

다섯 가지 중에서 톤에 가장 가까운 것을 고른다.

  • 담담·엉뚱 계열
  • 하이텐션·빠른 말투 계열
  • 감정 풍부·친근감 계열
  • 차분한 내레이션 계열
  • 기타

미세 조정하기

대사 본문을 훑어보고 수치를 고친다.

  • 40자 이상이면 말하기 속도를 조금 올린다
  • ‘!’가 있으면 억양을 키운다
  • 쉼표가 많으면 쉼을 길게 한다
  • 10자 미만의 결정적 대사는 앞뒤에 무음을 더한다

출력

표로 돌려준다. VOICEVOX 화면의 파라미터 순서와 같아서, 보면서 그대로 슬라이더에 옮길 수 있다.

신경 쓴 점

  • 수치는 ‘출발점’. 실측값이 아니라는 점을 매번 덧붙여요.
  • 수치로 만들지 않는 것도 있다. 의문형 억양이나 고유 명사의 악센트에는 ‘직접 확인 필요’라고 덧붙여요.
  • 수치를 지어내지 않는다. 말로만 적힌 것(예: ‘보통~약간 길게’)에는 수치를 붙이지 않아요.
  • 음성은 만들지 않는다. 음성 자체는 생성하지 않아요. VOICEVOX 화면에서 직접 반영해요.

설계의 선택

세 가지 방법을 비교했어요.

  • (A) 고정된 표만 쓰기
  • (B) 대사마다 규칙으로 조립하기
  • (C) 표를 바탕으로 규칙으로 미세 조정하기

안정감과 그 대사만의 개성을 함께 살릴 수 있는 (C)를 골랐어요(설계 기록 ADR 008).

만든 방법

설계를 한 뒤에 설명서를 썼어요. 프리셋과 미세 조정 규칙은 설명서에 고정된 내용으로 적어 두었어요.

기술 메모

  • Claude Code 스킬
  • VOICEVOX
  • Markdown
  • 설계 기록 (ADR)

WORK 3

③ 유학 가계부 (지출 기록과 예산 페이스 표시)

한마디로: 유학 중 지출을 스마트폰으로 몇 초 만에 기록하고, 이번 달 예산에 비해 어떤 페이스로 쓰고 있는지 볼 수 있는 저만의 웹 앱이에요.

해결하고 싶었던 고민

  • 캐시리스(카드 태그 결제)가 주류라서, 소액 결제가 하루에도 몇 번씩 있다.
  • 입력이 번거로우면 오래가지 않는다.

구조 (세 가지 부품)

화면

HTML과 JavaScript로 만든다. 그래프는 Chart.js.

계산

순수 함수만 모은 파일. 화면·데이터와 분리되어 있어서 Node.js로 테스트할 수 있다.

데이터

클라우드에 있는 작은 데이터베이스. 스마트폰에서도 컴퓨터에서도 같은 데이터를 쓸 수 있다. 개인용이라 로그인은 없다.

Claude의 Artifact(작은 웹 앱을 올려 두는 곳)로 만들었어요. URL 하나만 북마크하면 바로 쓸 수 있어요.

화면에서 할 수 있는 일

  • 지출을 빠르게 기록한다.
  • 이번 달에 쓴 금액을 예산과 비교해 본다 (하루 단위 페이스 표시 포함).
  • 날짜별 지출 그래프.
  • 잔액 전망.
  • 고정비와 변동비로 나눈 돈의 흐름.
  • 식사가 포함된 숙소의 경우, 식사 횟수에 맞춘 식비 예산 자동 조정.
  • 송금 계획 관리.

신경 쓴 점

  • 입력하는 수고를 최대한 줄인다. 설계에서 가장 중요한 제약이에요.
  • 계산을 화면에서 분리하고 테스트를 썼다.
  • 설계가 먼저. 기능마다 설계서와 구현 계획을 쓴 다음에 만들었어요.
  • 정한 것을 설계 기록(ADR)에 남겼다. 4개가 있어요.
    • 방학·식사 횟수 데이터는 계산 파일의 상수로 둔다.
    • 방학이 있는 달의 식비 예산은 식사 횟수의 비율에 따라 자동으로 늘리고, 표시에만 반영한다.
    • 송금 설정은 별도의 데이터 문서에 둔다.
    • 월별 자산 증감은 기록에서 계산한다.

만든 방법

기능마다 ‘설계서 → 구현 계획 → 테스트를 먼저 쓰고 구현’을 반복했어요.

기술 메모

  • HTML
  • JavaScript
  • Chart.js
  • Claude Artifact (데이터베이스 기능)
  • Node.js (테스트)
  • 설계 기록 (ADR 4개)
