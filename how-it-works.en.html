How My PKM (Personal Knowledge Management) Works

Here are two systems I built for myself as PKM (Personal Knowledge Management), explained with diagrams.

  • PKM 1: Study-Task Secretary
  • PKM 2: Overall Design of the Vault

SYSTEM 1

PKM 1: Automated Secretary for Study Tasks (morning notification and backward planner)

In a nutshell: It sorts out the assignments and plans piling up in my notes (Obsidian) every morning, automatically, and sends them to my phone. Working backward from deadlines, it tells me "it would be good to do this today", with the reason.

Problems I wanted to solve

  • Once a week gets going, next week's classes become hazy and my prep ends up last-minute.
  • Tasks overflow and I can't tell where to start.
  • I forget to open my notes in the morning.
  • Information just piles up in my notes, and it doesn't feel like it becomes mine.

How it works

Input

  • Weekly routines (a file listing prep, quizzes and so on, with weekdays and time needed)
  • Classes and plans (Google Calendar)
  • Registered tasks (in my notes)

Backward calculation

  • Starting from the nearest deadline, tasks are assigned to free time (excluding plans, meals and shopping).
  • Anything that doesn't fit is reported as "doesn't fit".
  • No AI is used; it calculates with fixed rules (so the result is the same every time, and it can be tested).

Output

  • Morning notification (sent automatically every morning from the cloud)
  • Web dashboard (for my phone, updated automatically every morning)

When I'm done: I tick the task in my notes, or tell the AI "I finished such-and-such".

The five components

  1. Notes (Obsidian, managed with Git) A task is a single line with fields such as deadline, date received and time needed. Tasks can also be broken down into parent and child tasks.
  2. Routine file Write down weekly prep, quizzes and so on, and it automatically creates the tasks for the next two weeks.
  3. Backward calculation As in the diagram above.
  4. Morning notification A scheduled run in the cloud bundles everything into one message each morning. It works even when my computer is closed.
  5. Web dashboard Today's plans, what to do next (four boxes of urgent × important), a 12-week calendar and the load for each week, all on one page. It is private.

Things I put thought into

  • Tracking completion rides on an existing action. Routines are created as real tasks, so ticking one is all it takes. No special screen or record is needed.
  • Resilience. Even if the planning part fails, the morning notification doesn't stop. Plans that couldn't be fetched are not overwritten as "no plans". The same task is never created twice.
  • Small features to keep me using it. If I forget to create something, the morning notification tells me. Importance can be switched on and off with one button.
  • Preparing for timing drift. I found that scheduled cloud runs can be late or skipped at busy times. So I shifted the time, and added a second run as insurance plus a check to prevent double sending.

How I built it (development process)

Together with AI (Claude Code), I wrote a design document, decision records (ADR) and an implementation plan, and then implemented it test-first. For each piece of work, the implementer and the reviewer are separate roles, and everything goes through a final overall review. It is written in Node.js with no dependency libraries, and has 24 test files.

Tech notes

  • Node.js (no dependencies)
  • Obsidian + Dataview
  • Git
  • GitHub Actions (scheduled runs)
  • Notifications to Discord
  • Google Calendar
  • Scheduled AI runs in the cloud
  • HTML + plain JavaScript
  • Test-first development
  • Design records (7 ADRs)

SYSTEM 2

PKM 2: Overall Design of the Obsidian Vault

The Vault (a storage space for notes) uses numbered folders to represent the "flow of information".

Folder map

Table of folder names and their roles
FolderRole
00_InboxA catch-all for unsorted items
10_FleetingTemporary items (daily and weekly notes, and where new tasks get written)
20_LiteratureLecture notes, reading notes and English vocabulary
30_ZettelConcept cards (knowledge written in my own words)
40_MOCTables of contents and dashboards
50_ProjectsProjects being carried out
60_ReviewReview questions (choice + reason). The answers become seeds for concept cards
80_SystemThe machinery itself (templates, scripts and routines)
90_ArchiveCompleted and stored

The five layers

  1. ①Intake layer

    Lectures and reading. Lecture notes follow a template (summary, lecture memo, unfamiliar vocabulary, next actions, key concepts). For each course there is a note summarising grading and schedule, and a note on current assignments.

  2. ②Task layer

    A uniform one-line format (deadline, date received, time needed, status). New tasks go into a single catch-all. Weekly routines are turned into tasks automatically. Importance is one button.

  3. ③Timeline layer (viewing)

    Calendar-style plugins, Dataview lists, a Gantt chart, and the web dashboard for my phone.

  4. ④Automation layer

    Node.js scripts (no dependencies, 24 test files), the morning notification via GitHub Actions, scheduled AI runs in the cloud (dashboard updates), and QuickAdd macros.

  5. ⑤Knowledge layer

    When I answer a review question with a reason in my own words, it becomes a seed for a concept card. I have the AI look for connections between notes.

Flow of information

  1. Lectures and reading
  2. Lecture notes
  3. Next actions
  4. Task
  1. Routines
  2. Task
  1. Calendar
  2. Backward calculation
  3. Morning notification, web dashboard and Obsidian lists

When I'm done, I tick the task in my notes.

Dividing the work with AI

The rules are written in instruction sheets inside the notes, and the AI reads them every time. AI "skills" help with transcribing lectures, reaction papers, exam preparation, registering tasks, reviewing, updating the dashboard and so on. The calculation is not left to AI; it is done by scripts with fixed rules. The AI's role is to write, summarise and carry out procedures.

Where the data lives and how it syncs

The whole Vault is a private Git repository. It is committed and pushed automatically. The morning notification and the dashboard read the copy on GitHub. Secrets (the notification destination, the calendar URL) are not put in the repository; they are kept in the cloud's secret storage.

Where things stand (honestly)

  • Used a lot: lecture notes, tasks, the morning notification, the dashboard and the calendar.
  • Not grown yet: concept cards and review questions (I'll add more from now on).
  • Still left over as old: routines from a previous term (already moved to the new routine file).
